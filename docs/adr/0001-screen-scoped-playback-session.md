# Playback session владеет плеером экрана; смена серии — через навигацию

История коммитов `3ad8250 → 28dfa1f → 78f7954 → 60f5de1 → 2bfeba4` — пять подряд фиксов «чёрный экран при смене серии», качели между общим плеером, TextureView-хаками и screen-local плеером. Решение: модуль **Playback session** (core:player) сам создаёт, владеет и освобождает ExoPlayer и живёт ровно столько, сколько живёт экран видео (создаётся на nav-destination, закрывается при уходе с экрана — тот же жизненный цикл, что у прежнего screen-local плеера). Смена серии остаётся навигацией на новый route (новый экран → новая сессия → новый плеер), а не переиспользованием одного плеера.

## Considered Options

- **Долгоживущий плеер уровня activity/service** — отклонён: проблемы жизненного цикла surface при смене контента — источник багов `2bfeba4`/`28dfa1f`; фоновое воспроизведение осознанно удалено в `06d06ac`.
- **Экран создаёт плеер, сессия только политика** — отклонён: два владельца жизненного цикла (composable + ViewModel) и есть причина качелей в истории.

## Consequences

- Каждая серия пересоздаёт плеер и перерезолвит Stream URL — приемлемая цена за корректный жизненный цикл.
- Воскрешать общий плеер или фоновое воспроизведение — только через новый ADR.
